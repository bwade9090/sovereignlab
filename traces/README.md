# Execution trace policy

`replay/v1/` contains the small public `ExecutionTrace` 1.0.0 artifacts generated by the fixed
offline scenarios in `scripts/export_execution_replay_traces.py`. Each JSON file is produced by
the private offline executor against the committed callable registry, composite artifact registry,
complete synthetic retrieval corpus, and a digest-linked scripted plan. It is not hand-authored
provenance and it contains no provider response envelope, credential, or machine-local path.

Regenerate or check the exact UTF-8/LF bytes from the repository root:

```powershell
.\.venv\Scripts\python.exe scripts/export_execution_replay_traces.py --write
.\.venv\Scripts\python.exe scripts/export_execution_replay_traces.py --check
```

The five scenarios cover all four routes, all three deterministic tools, Korean and English,
explicit and harness-fixed implicit cutoffs, complete packets, planned abstention, and a terminal
tool abstention after a successful prefix. The terminal-abstention plan contains a later valid STES
call that is not run, and its packet intentionally contains no partial evidence.

The healthy committed stack does not naturally produce planner, tool-execution, or packet-assembly
faults. Those phase mappings remain covered by strict schema and executor regression tests. They
are not presented here as real-digest end-to-end outputs because injecting a runtime fault would
not be represented by the recorded executor and environment digests.

The synthetic document passages remain synthetic fixtures. This public replay set follows the
repository's non-commercial public-research profile. Selected ECOS and OECD observations retain
their recorded provider terms, attribution requirements, manifests, and owner-approved rights
decisions; repository Apache-2.0 terms do not relicense those source observations.

must never be promoted into this public replay set.
