# K-VINTAGE tier-2 probes

Machine-generated, deterministic questions about Korea's OECD composite leading indicator (CLI)
whose gold answers depend on the data vintage available at each question's `as_of` date. They are
drafts made by a program, not human-reviewed records. Report them separately from the
human-reviewed core in [`../core/`](../core/), and never add the two counts together.

## Probe set v1

`kv-probes-oecd-cli-v1.jsonl` holds 278 `BenchmarkRecord` 2.0.0 lines (139 Korean/English
pairs), generated by `sovereignlab.probes` from evidence version 2 (ADR 0013). ADR 0014 records
the design and the split decision.

```bash
python scripts/generate_probes.py --check   # confirm the file equals a fresh generation
python scripts/generate_probes.py --write   # regenerate after changing the generator
```

Both commands print the composition below. There are two families, each asked as a pair:

- **As-of value** (route `data`). Korea's CLI for one month, as published in the edition that the
  availability ledger selects at the cutoff. Every month from January 2023 to the edition's last
  month is asked. A record is tagged `revision-trap` when any later edition in the admitted
  archive holds a different value for that month, so an answer taken from that edition is
  detectably wrong; otherwise it is tagged `unrevised`. The later editions include `202609`, which
  no cutoff can select. Every trap pair but one also differs from the newest edition, `202611`:
  May 2023 in edition `202607` was revised only in `202609`, and revised back in `202610`. These
  266 records are the charter's tier-2 data-route items.
- **Future period** (route `abstain`). One of the two months after the edition's last month. The
  gold is abstention, because any number would come from a later vintage. This family goes beyond
  the charter's "data-route" wording, so report its 12 records as a family of their own.

| Edition | Split | Cutoffs (Asia/Seoul) | As-of value | Revision traps among them | Future period |
| --- | --- | --- | ---: | ---: | ---: |
| `202607` | train | 2026-07-08 to 2026-07-16 | 84 | 84 | 4 |
| `202610` | test | 2026-10-08 to 2026-11-08 | 90 | 40 | 4 |
| `202611` | dev | 2026-11-10 to 2026-11-22 | 92 | 0 | 4 |

Counts are records. Every cell splits evenly between Korean and English.

### How the gold is made

- **Cutoffs.** An edition's window is every day on which the ledger selects it. Items take the
  window's days in turn, so its first and last days are both used.
- **Gold.** The `resolve_stes_as_of` result for the record's exact typed arguments, recorded as
  the selected edition, raw value, normalization rule, normalized value, unit, display places, and
  display value. Generation stops if the resolver selects another edition, or does not abstain
  with `missing_selected_row` for a future month.
- **Splits.** Each edition is one evidence group in one split. `202607` is train because the core
  already uses it there; the owner chose `202610` for test on 2026-11-24, which also makes it the
  core's reserved test-split data release; `202611` is dev. A core record may use an OECD edition
  only in that edition's probe split.

`tests/benchmark/test_probes.py` checks that the file regenerates byte for byte, that the probes
and their evidence form one valid `BenchmarkBundle`, that the typed tool dispatcher reproduces
every data probe, and the composition above. `tests/benchmark/test_core.py` checks the split rule
for the core.

### Limitations

- One series and three dated editions. The 329 editions before `202607` have no dated
  availability, and cutoffs from 2026-07-17 to 2026-10-07 abstain because of the capture gap
  (ADR 0013), so no probe uses them.
- Dev has no revision traps yet, because no admitted edition is newer than `202611`. Probe set v1
  stays pinned to evidence version 2; a later evidence version would yield a new probe set under
  its own ID.
- The questions follow one template per family and language. They test cutoff and vintage
  discipline, not language understanding or document use.
- Months before January 2023 exist in each edition but are not asked.

## Human audit

The charter requires a documented human audit of a sample.

**Status: pending.** The owner has not audited the sample yet. A probe result reported before the
audit is recorded here must say that the set is unaudited.

**Sample:** all six future-period pairs, and every tenth as-of value pair in file order starting
with the first. That makes 20 pairs (40 records), covering every edition, both tags, and both
families.

| Family | Pairs (`kv-probe-cli-` prefix omitted) |
| --- | --- |
| Future period | `future-202607-2026-07`, `future-202607-2026-08`, `future-202610-2026-10`, `future-202610-2026-11`, `future-202611-2026-11`, `future-202611-2026-12` |
| As-of value, `202607` | `asof-202607-2023-01`, `asof-202607-2023-11`, `asof-202607-2024-09`, `asof-202607-2025-07`, `asof-202607-2026-05` |
| As-of value, `202610` | `asof-202610-2023-09`, `asof-202610-2024-07`, `asof-202610-2025-05`, `asof-202610-2026-03` |
| As-of value, `202611` | `asof-202611-2023-04`, `asof-202611-2024-02`, `asof-202611-2024-12`, `asof-202611-2025-10`, `asof-202611-2026-08` |

For each sampled pair, check the following.

1. The Korean and English questions ask for the same month, cutoff, and series, with no
   answer-bearing translation difference.
2. The cutoff is in the edition's window. In the active v2 ledger,
   `data/availability/oecd-stes-ledger-20261123t104316607555z.json`, the edition's `available_by`
   is before the end of the cutoff day in Asia/Seoul. No newer edition is available by then, and
   none is unresolved.
3. *As-of value:* the archive `data/archive/oecd-stes/oecd-stes-cli-kor-li-aa-20261124t010648941132z.csv`
   has a row with this `EDITION` and `TIME_PERIOD`, and its `OBS_VALUE` equals `raw_value`. The
   display value shows it to two decimal places.
4. The `revision-trap` tag is present exactly when a later edition's row for that month differs.
5. *Future period:* the edition has no row for the month, and its last month is the one the
   abstention reason names.
6. Both answers attribute the OECD and imply no endorsement.

This prints every edition's value for one month:

```bash
python -c "import csv, sys; [print(r['EDITION'], r['OBS_VALUE']) for r in csv.DictReader(open(sys.argv[1], encoding='utf-8-sig', newline='')) if r['TIME_PERIOD'] == sys.argv[2] and r['EDITION'] >= '202607']" data/archive/oecd-stes/oecd-stes-cli-kor-li-aa-20261124t010648941132z.csv 2026-05
```

Record the outcome under this heading: the date, the auditor, the pairs checked, and any error
found. If an error is found, fix the generator, regenerate the set, and audit the sample again;
never edit records by hand. The audit checks the generator, so it changes no record's annotation.
